# CPU-native simulation continuously feeding a single-GPU RL learner

Status: implementation authorized on 2026-09-30. The user approved the planned code, dependency/lock, adapter semantics, and closed schema cutover, selecting CPU simulation plus GPU inference/training and measured at least 95% sustained useful-work GPU saturation. The design and planning evidence below do not constitute implementation, qualification, or performance results. WP-05C/WP-06/cost records must be verified or generated, never fabricated.

## 1. Architecture decisions

- CPU: native game workers, exact RiichiEnv rules core, canonical actions/events, actor-visible observation construction/validation, semantic RNG, tensor-plane filling, compact trajectory storage, streaming canonical artifact validation/publication.
- GPU: BF16 policy/value forwards, legal categorical sampling, FP32 log probabilities, batched terminal return/advantage construction, bounded tensor replay cache, masked PPO forward/loss/backward/clipping/fused AdamW.
- ONE CUDA owner alternates useful inference and learner microsteps on one compute stream; transfers use one separate stream. No shared actor/learner parameter mutation race. The immutable actor is eval+inference_mode; the learner is eval+autograd. This intentionally disables dropout for both RL paths without changing the architecture/weights. Supervised training remains unchanged.
- Train sealed generation g while collecting g+1 under its own durable frozen behavior checkpoint. Maximum ONE lookahead generation. This has bounded policy lag, not zero-lag/on-policy synchronization. The existing frozen-artifact clipped PPO objective remains unchanged; no V-trace, ACH, adaptive KL stop, extra epochs for utilization, shaping or temperature changes.
- Initial selfplay: all four seats use the same frozen behavior checkpoint, so every row can match the artifact's single behavior header. Historical opponent catalog remains immutable; when using a predeclared mixed-opponent schedule, only behavior-controlled seats produce learner rows. Historical opponents are not silently relabeled as the learner.
- Native code goes under existing crates/bridge/src/rl/ rather than a new workspace crate. This conservative integration reuses bridge-local observation gates, RNG, canonical table state and encoder primitives without a dependency cycle or second implementation. Keep the Rust pool/game logic separate from the thin PyO3 API within that subtree; no per-row Python callbacks. hydra-feed remains the canonical IO/JCS owner. The earlier suggested separate crates/rollout is rejected for this cutover.
- Exact dependency proposal: riichienv-core from https://github.com/smly/RiichiEnv at rev479c1faeb33d082965eef8198f63261a79c0fce3 (verified v0.4.10), default-features=false. Native core package version0.4.10, Apache-2.0, edition2024, optional Python feature disabled. New dependency/lock changes require approval. Core rules are reused, NOT rewritten; Python adapter is the differential oracle.

## 4. Native interfaces, buffers and state machines

Rust modules: rl/{mod,ffi,core,actions,events,observation,pool,trajectory,artifact,snapshot,wall}.rs. PyO3 API only ffi.rs, exported through mod.rs; Python rl_bridge.py is typing/lifetime/firewall + batch calls (~100LoC). Torch-specific code in rl_loop.py/rl_gpu.py/rl_objective.py stays modest separate modules; no Python trajectory loops/hashes/validators. Extract needed pure typed helper bodies within existing Rust gate/RNG/encoder modules, migrate existing callers, retain public Python function contracts, remove duplicate bodies. No new shared-framework crate or fallback backend.

APIs (all batch/owner-level):
- NativePool.open(immutable_profile, rules/utility/action/observation/seed/wall-ledger/opponent identities) -> pool; cold checks entire geometry/frozen table identity once plus per-state gates.
- register_buffers(bucket_T,slot_id,host_input_u8_span,host_output_u8_span,capacity_bytes) -> registration. Strong PyO3 owners kept until all workers/leases close; CPU pinned, contiguous, correct geometry/dtype/ranges, nonoverlapping slots required. No raw pointer outlives its owner. CUDA tensors/events remain physically owned by torch.
- request_ready_fill(free_slot) schedules native typed fill; peek_ready() searches ALL eligible READY tickets and is nonblocking. No work means no eligible ticket, not an earlier bucket still filling. Descriptor: slot_id,slot_epoch,generation,logical_round,chunk_index,bucket_T,n_valid,policy_checkpoint_id,schema_id,ordered decision keys/handles, active layout, reserved stream cursors. In initial selfplay policy_checkpoint_id equals behavior header; mixed-opponent requests are separately grouped and never mislabeled.
- Version carrier is EXACTLY (policy_checkpoint_id,generation,slot_epoch): immutable checkpoint ID binds weights, generation binds collector lineage, slot_epoch detects physical reuse. "Epoch" in lease validation means slot_epoch, not an unspecified policy counter. No additional policy_epoch/global counter is necessary. Descriptor ordering is (generation,logical_round,policy_checkpoint_id,T,chunk_index); grouping occurs inside that frozen generation/round. Opaque lease also binds its owning pool/registration, so an old pool's handle cannot commit into a restored/new pool.
- Ready input: existing26 baseline feature planes in frozen dtypes plus uniform[B]binary64. Pack ACTIVE B using precomputed active-B offsets inside capacity raw slabs; one contiguous H2D of active bytes, cached torch views for (slot,B,T). Do not copy unused capacity or allocate/rebuild per-row Python metadata. Native lease retains real observation hashes/decision identities; tensor identity-free math cannot waive their validation.
- GPU outputs to registered pinned slabs: selected_action_id[B]int64 (gather-compatible), old_selected_logp[B]FP32, behavior_value[B,4]FP32. 28bytes/real row plus fixed alignment. RNG cursor_after is already in native lease, not redundantly copied from GPU.
- commit_actions(lease,output_span) first validates ENTIRE batch (finite logp/value, exp(logp) valid objective dtype, ids/ranges/legal membership, decision/actor/version/epoch/cursor match), captures owned transition facts, then dispatches native applies in deterministic game order. Failed apply/panic poisons generation; no rollback-as-success/no coercion. Pure Rust worker errors return on owner poll/drain/close; no PyErr/Python callbacks in worker hot path.
- Input/output lease: FREE -> FILLING -> READY -> H2D_ISSUED -> INFER/SAMPLE_QUEUED -> D2H_ISSUED -> HOST_READY -> OWNED_CAPTURE -> FREE. Free only after last compute read of device input/mask, D2H completion of device output, and native capture of host results. GPU consume event is NOT merely an H2D-done event. Conservative paired lease holds all buffers until capture; CPU game evolution then continues without holding GPU buffers.
- One outstanding actor decision/game. Native handles include generation/slot epoch; stale commit, double commit, close-with-live-work, undersized spans or identity drift fail closed. close() NEVER waits for leases that only its blocked caller can release: it rejects live work, then joins after explicit owner-driven quiesce/drain/capture has completed. Strong registered owners remain alive through join. No silent pageable/Python fallback. Existing supervised PinnedRing remains unchanged; RL implements the additional lease protocol separately.

## 5. Continuous scheduling and frozen policy handoff

Native-live path (2026-10-04, pipeline v3 `training_source='native_live_v1'`, `recovery='generation_restart_v1'`): live training consumes Rust-owned typed trajectories without canonical rollout export, seal/materialization, or runtime-control publication gating learning or actor activation. Policy identity includes the pipeline/derivation recipe, which intentionally changes pipeline and policy identities and therefore the associated sampler/shuffle streams; no old-versus-new trajectory identity claim is permitted. Recovery restores an atomically paired generation-boundary learner state and frozen behavior actor, then regenerates the unfinished generation from its initial semantic counters. Old sealed-run control tips are not restart inputs. Fixed cohorts, exactly eight generations, one epoch, unchanged PPO/return math, and at most one future generation remain mandatory. The paragraphs below describe the sealed-source history; where they mandate seal/materialization, tape/pool/control durability, or ordinary-actor publication before activation, the live path above governs production.

Warm start model weights only from validated IL checkpoint; initialize fresh RL AdamW/scheduler/state, not supervised moments. C0 is the validated immutable baseline policy. Collect/drain A0 live before learner can train: real cold-start fill is unavoidable, count it.

Steady state:
1. Learner g consumes only validated immutable A_g under frozen RunSpec_g and precomputed minibatch order. It starts from the final LEARNER checkpoint of g-1, not necessarily behavior C_g.
2. Live: after the first completed optimizer update of g (with learner inactive and old collection fully complete/drained), drain remaining issued old-actor work, copy the frozen actor in CUDA order outside autocast (`copy_actor_at_boundary`), compute C_(g+1) via the lineage identity, create only the one future collector, and resume admission. No CPU tensor snapshot, checkpoint hash, fsync, or writer future gates this activation. (Sealed-source history: snapshot learner, publish ordinary actor checkpoint durably, then activate.)
3. Native collectors produce g+1 while GPU alternates train microsteps and actor requests. At most one future generation; a completed future typed replay backpressures NEW ADMISSION, not worker execution needed by already admitted apply/fill/drain. No blocking completed-future queue occupying those workers, unlimited stale replay or mixed headers/sources.
4. A logical collection round has one pending decision per nonterminal cohort game. Freeze the complete membership, then group by (policy_checkpoint_id,T), sort decision keys and slice to cap128. Independent group fills may become READY in any order; choose the stable lowest descriptor among currently READY tickets, never wait for a lower-T FILLING ticket. This changes service order, not fixed batch membership/shape. Freeze the next round only after every current-round commit/native apply completes; retain already prepared per-game candidates without arrival-based regrouping. Terminal games retire; no first-finished replacement.
5. GPU microstep = complete learner forward+loss+backward; actor inference is admitted BETWEEN microsteps, never against mutating actor/shared learner tensors. Drain completed D2H captures first; alternate at most one eligible inference ticket and one available learner microstep, but immediately use the other class when the preferred class lacks work. Enqueue bounded next-ticket H2D while current compute runs when its paired slot is free; stream dependencies gate compute/D2H and no lease is recycled early. Overlap is enabled, NOT guaranteed by depth2. At each optimizer boundary reduce finite flags, clip/step/scheduler exactly once. No extra epochs, polling sleep or dummy work. Fixed shapes, immutable policy and per-game streams make interleaving semantically irrelevant; deterministic qualification must prove it.
6. When g completes, capture the generation restart boundary snapshot (paired learner-final plus frozen actor, `hydra2.rl_restart/v1`) without delaying the handoff, then swap future→current and train it. If producer is late, record it as producer lateness; don't pretend continuous work or run extra epochs. End last generation with the terminal restart checkpoint and observer-only evaluation. (Sealed-source history: checkpoint learner, select A_(g+1) after full validation, freeze new RunSpec.)

Policy publication does NOT hash async collector progress into policy or shuffle identity (section7). Autocast is scoped per forward/loss invocation; a long-lived cached BF16 actor weight cache must not survive snapshot replacement. Native RNG has no dependency on GPU queue timing. Parameter/device-buffer ownership, stream ordering and fixed logical batch membership are separate guarantees.

## 6. Artifact/return/sampling/objective laws

Live training source (2026-10-04): the production loop drains completed Rust-owned cohorts (`drain_tape`), freezes terminal advantages once, and registers typed replay directly (`register_live_replay`) with slot fills (`fill_live_slab`). There is no canonical rollout export, seal/materialization, tape/pool file persistence, or runtime-control publication on the production path; those remain offline archive/qualification tools. Bullets below describing seal/tape/pool/control durability are sealed-source history, except the sampling/return/objective math, visibility, ordering, and geometry laws, which are unchanged.
- Per-generation cohort wall/game IDs + seating are fixed before collection; no first-N-finish cutoff. Source wall ledger is disjoint from final-evaluation wall authority; master seed scopes selection_training vs final_evaluation remain separate. Initial all-seat selfplay; explicit immutable opponent schedule if mixed.
- Capture committed rows in native compact records: actor-visible scalar snapshot/concealed/drawn/dora5/legal IDs, references to immutable typed per-kyoku event prefixes, action/logp/value4/stream cursor/transition provenance. Typed event arenas are append-only with index references, not mutable old-row views or cloned history per step. Retain all information needed to reproduce the external observation; tensor features alone cannot reproduce complete event documents.
- Two mandatory observation identity/visibility checks remain: builder binding + independent validator re-derivation. Never bypass them; removing Python staging/getattr is the optimization. Round/claim/kan/red-tile/draw semantics match the CORRECTED, requalified Python adapter, not its reproduced ordinal defect. Native core auto-wall RNG cannot replace frozen continuation walls. Exact pinned NumPy2.5.3 PCG64/SeedSequence/permutation native law is specified in section13; its SHA fallback and other RNGs are different.
- Complete cohort terminal outcomes -> existing rank utility mapping -> canonical G4; batched GPU FP32 return/advantage gather (wire G values remain original canonical manifest floats, not rounded overwrites). Native validates expected shapes/finiteness/utility lineage and freezes recipe/sampling/numeric dtype/code hashes in row_derivation_hash. Store no BC fields at w_bc0.
- Per-game/seat/behavior semantic stream, actor_policy_sample: case_id=opaque unique game id, candidate_id=canonical behavior checkpoint id, root_seat=seat, replicate/attempt explicit, wall_id null (exactly one case/wall). Exactly eight bytes reserved once per real decision, even forced singleton. u=(u64BE >>11)*2^-53, binary64 [0,1) exactly. Existing random_float division can round to1; do not use it or silently force last legal action. Padding draws none.
- GPU legal log probability primitive: masked FP32 log_softmax, illegal=-inf; selected stored LP is FP32, objective exponent finite and0<pi_old<=1. Sampling uses exp(logp) promoted to FP64, cumulative sum, normalize all bins by that row's FINAL cumulative value, then strict upper-bound search (firstCDF>u). FinalCDF=1; zero/illegal plateaus cannot select. No last-action repair/clamp/fallback. Stored LP describes the FP32 policy; normalized FP64 categorical sampling is the explicitly qualified finite-precision convention. Same-checkpoint probabilities/logp/value and ratio~1 must pass cross-shape allclose(atol=1e-6,rtol=1e-5); never silently loosen tolerance.
- External row order EXACTLY (wall_id,game_id,trajectory_step,actor,decision_id,row_id). row_id=SHA256(JCS complete row excluding row_id). Dedup, step monotonicity, selected legality, mask/observation identity/header/split/provenance all validated. RLO digest=SHA256 of FULL canonical root byte stream excluding digest, not SHA(previous_root||row_hash). Stream expanded rows via shared JCS emitter, bounded row/chunk memory; compressed storage hashes canonical decompressed bytes. Every row validated before learner admission, no spot checks. Sorted row-ID index and compact feature cache bind frozen wire facts; no expanded Python tuples.
- Staged JSON emission writes arrays, booleans, delimiters and escaped strings directly, sorting object keys by UTF-16 only when their existing order differs. Numbers retain the pinned JCS formatter and unsafe-integer rejection remains unchanged. This removes per-token boxed writers from dense legal masks without changing canonical bytes, row IDs or artifact identity.
- Observation materialization moves staged visible-history event trees and legal-mask values into the final document rather than reserializing them through the JSON construction macro. This preserves actor visibility, hand scoping, exact fields and independent identity re-derivation while avoiding redundant per-event copies.
- Learner CUDA replay retains only the active history bucket's private autograd pool. At a completed optimizer boundary, synchronize the owner stream and release obsolete bucket graphs before capturing a new bucket; retaining all bucket activation pools exhausts VRAM during overlapping actor collection.
- Each learner bucket captures FIRST, ACCUMULATE and transfer graphs on its own retained capture stream, then replays them on the sole compute-owner stream. In pinned Torch 2.14, graph destruction clears cuBLAS workspaces by capture stream; sharing the actor capture stream would invalidate surviving actor graph addresses when a learner bucket is retired. Capture-stream isolation preserves bounded bucket reclamation without retaining obsolete activation pools.
- Seal pass two emits the independently reproduced no-ID row once, checks its SHA-256 against the admitted identity, and inserts the `row_id` field in place at a canonical root-suffix boundary. The closed ASCII root schema makes this boundary unambiguous even with nested same-named keys or escaped strings. A frozen 111,893-row replay preserved all 15,145,018,716 canonical bytes, compressed transport bytes and metas bytes against the retained fixture; local portable timing was 122.347 seconds (concurrent-job conditions, not a standalone speedup qualification).
- Event envelope projection moves already-staged payload, public-delta and delta-path trees into its result rather than passing them through `json!` a second time. The fixed 111,893-row replay retained the same canonical artifact digest, transport length and metadata identity; the observed portable seal time was 109.645 seconds under concurrent load, not a controlled speedup claim.
- Independent observation identity validation canonicalizes borrowed root entries excluding only `observation_hash`; nested same-named keys and unsafe-integer rejection remain unchanged. It does not clone the complete history tree. The 111,893-row fixed replay retained canonical digest `e956fd2e310c24ff28327960d154b9a671543d7e23b38dc62eb8c808b035e525`, 54,977,547 compressed bytes and 15,145,018,716 expanded bytes; observed seal time was 96.655 seconds, with no saturation or controlled speedup claim.
- Guarded integer `Value` numbers emit exact decimal JSON directly: their magnitude is at most `2^53-1`, below JCS's exponent boundary. Floating values retain the pinned JCS formatter for negative zero and exponent rules. The fixed 111,893-row seal reproduced the same digest and lengths in 84.004 seconds under concurrent test load; this is not a useful-GPU saturation measurement.
- Approved native parallel sealing keeps two independent passes and one ordered SHA-256/zstd writer. At most `workers * 8` expanded row buffers are staged per output window, with `1..20` native workers bounded by available CPU parallelism; Python submits one seal job and never dispatches rows. Worker errors or panics reject the seal, and no partial output becomes authoritative. The prior one-expanded-row memory restriction is replaced by this bounded window within the existing 12 GiB host budget.
- The bounded parallel seal's fixed 111,893-row smoke produced the identical canonical digest, compressed transport bytes and metas bytes in 25.691 seconds on CPU affinity 8–19. This observation includes concurrent suite load and is not a controlled throughput or GPU-saturation claim. All 598 native bridge tests passed, including ordered tails and worker error/panic rejection.
- Inference fills select eligible games and buckets in cohort order, then dispatch observation construction and identity checks to the existing fixed native worker pool. Ordered result collection retains row order and reserves sampler words only for selected real decisions; capacity overflow does not consume draws. Engine applies and observations share per-game locks. The single-fill guard, logical-round barrier, serial tensor-plane encoding and owner-side buffer copy remain unchanged; this is not an autonomous producer or a saturation claim.
