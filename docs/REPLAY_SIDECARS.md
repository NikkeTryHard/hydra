# Hydra Replay Sidecars

Ops guide: Hydra replay-side supervision artifacts: ExIt sidecars, DeltaQ sidecars.

Doc says builder emit, training consume, provenance checks must match before Hydra hydrates replay-time labels. High-level training entrypoint: [`docs/TRAINING_WORKFLOWS.md`](TRAINING_WORKFLOWS.md).

## What a replay sidecar is

Replay sidecar = offline JSONL artifact keyed to replay decisions. Carries supervision Hydra not want recompute inline during normal replay load.

Hydra supports two replay-sidecar lanes:

- ExIt sidecars
- DeltaQ sidecars

Both generated from:

- replay input (`.json` or `.json.gz`)
- checkpoint identity
- source version

Both can join during replay load if replay decision keys + provenance checks match.

## Shared CLI shape

Both sidecar builders use same shared CLI skeleton:

```bash
build_replay_*_sidecar \
  --input <replay.json|replay.json.gz> \
  --checkpoint <model_base> \
  --output <sidecar.jsonl> \
  --source-version <u32> \
  [--min-visits <u32>] \
  [--hard-state-threshold <f32>] \
  [--max-kl <f32>]
```

Shared flags live in `crates/hydra-train/src/bin/common/replay_sidecar_common.rs`.

### Shared flag meaning

| Flag | Meaning |
|---|---|
| `--input` | Replay source file to analyze |
| `--checkpoint` | Model base/checkpoint identity for label generation |
| `--output` | JSONL sidecar output path |
| `--source-version` | Version tag stored in sidecar; required again at join time |
| `--min-visits` | ExitConfig visit budget threshold override |
| `--hard-state-threshold` | ExitConfig hard-state threshold override |
| `--max-kl` | ExitConfig KL safety-valve override |

## ExIt sidecars

ExIt sidecars generated by:

- `crates/hydra-train/src/bin/build_replay_exit_sidecar.rs`

Output record type:

- `ReplayExitRecordV1`

Important fields in each record:

- replay decision key
- selected action
- legal-mask digest
- `source_net_hash`
- `source_version`
- root visit count
- supported action count / coverage
- target array and mask array

Conceptually, ExIt sidecars capture replay-indexed search-derived labels for root decisions so training can hydrate ExIt supervision without re-running full live search pass on every replay load.

## DeltaQ sidecars

DeltaQ sidecars generated by:

- `crates/hydra-train/src/bin/build_replay_delta_q_sidecar.rs`

Output record type:

- `ReplayDeltaQRecordV1`

Important differences from ExIt sidecars:

- DeltaQ requires `source_version == 1`
- validation contract stricter for legal actions and target/mask semantics
- lane still not default-on though tooling exists

Conceptually, DeltaQ sidecars capture replay-indexed child-minus-root value deltas for supported discard actions.

## What `source_version` and `source_net_hash` do

Hydra uses both `source_version` and `source_net_hash` as provenance identity when replay load tries hydrate labels from sidecars.

- `source_net_hash` comes from checkpoint identity
- `source_version` is operator-supplied version tag

Hydra refuses sidecar-label hydration when these mismatch replay loader expected provenance.

Deliberate. Sidecars not generic labels; contract-bound artifacts tied to replay identity, checkpoint lineage, versioned semantics.

## How replay loading consumes sidecars

Replay loading uses sidecars only when all relevant checks pass.

That includes:

- replay identity / decision key match
- action match
- semantic/provenance version match
- legal-mask digest match
- `source_net_hash` match
- `source_version` match

### Identity matching for loose files versus archives

Source-identity part of contract intentionally differs by replay shape.

- Loose replay loading joins sidecars by replay file name Hydra loads, not absolute host path.
- Archive-backed replay loading joins sidecars by explicit archive-entry identity string, e.g. `replays.tar.zst/path/inside/game.json`.
- So sidecar record keyed only to `game.json` matches loose replay load of `game.json`, but not archive entry whose identity is `replays.tar.zst/path/inside/game.json`.

This matters because Hydra treats archive entries as first-class replay identities, not anonymous extracted files. Avoids accidental collisions between different archive entries sharing same base file name.

Operationally:

- if you generate or inspect sidecars for loose replay files, expect file-name identity semantics
- if you generate or inspect sidecars for archive-backed replay corpora, expect full archive-entry identity semantics
- if sidecar looks structurally valid but hydration does not happen, mismatched identity shape is early check

For ExIt, lookup returns target/mask arrays when sidecar contract matches.

For DeltaQ, Hydra also validates:

- target/mask arrays have expected action-space shape
- masked actions are legal discard actions
- non-masked entries do not carry stray target mass

Why replay sidecars safe for optional replay supervision, not blind annotation files.

## How to make training consume them

Training consumes replay sidecars through config fields:

- `exit_sidecar_path`
- `delta_q_sidecar_path`

When configured, replay loading tries sidecar hydration during replay decision prep and target construction.

Use this when:

- you want replay-time ExIt or DeltaQ supervision without recomputing labels on fly
- you need reproducible sidecar provenance tied to specific checkpoint/version pair

## Example workflow

### Generate an ExIt sidecar

```bash
cargo run -p hydra-train --bin build_replay_exit_sidecar -- \
  --input /data/game.json.gz \
  --checkpoint /models/model_base \
  --output /output/game.exit.jsonl \
  --source-version 7 \
  --min-visits 128 \
  --hard-state-threshold 0.35 \
  --max-kl 1.5
```

### Generate a DeltaQ sidecar

```bash
cargo run -p hydra-train --bin build_replay_delta_q_sidecar -- \
  --input /data/game.json.gz \
  --checkpoint /models/model_base \
  --output /output/game.delta_q.jsonl \
  --source-version 1
```

### Consume them in training

```yaml
exit_sidecar_path: /output/exit_index.jsonl
delta_q_sidecar_path: /output/delta_q_index.jsonl
```

## Reports

Both builders also emit JSON report next to JSONL output. Report path derives from output path via `.report.json` sibling artifact.

Use report to inspect:

- how many labels emitted
- lane-specific validation/coverage summaries

## When to use ExIt vs DeltaQ

Use ExIt sidecars when:

- you want replay-indexed search-derived root/visit-style supervision
- you work on shipped baseline ExIt carrier

Use DeltaQ sidecars when:

- you evaluate or train narrow DeltaQ lane
- you are prepared to keep provenance and version contracts tighter
- you understand lane is implemented but not default-on

## Common failure modes

- Wrong `source_version` -> join-time hydration fails.
- Wrong checkpoint identity -> `source_net_hash` mismatch.
- Legal-mask drift blocks hydration even when replay looks similar.
- DeltaQ sidecars reject records that violate discard-only mask contract.
- Valid JSONL alone not enough; semantics/provenance must also match.
